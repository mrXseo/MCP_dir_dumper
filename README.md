
# Dumper

**Dumper** — это утилита командной строки для генерации текстовых дампов структуры директории и содержимого файлов.  
Проект использует плагинную архитектуру: каждый плагин отвечает за свою секцию дампа (например, дерево каталогов или содержимое файлов). Конфигурация задаётся через JSON.

## Возможности

- Рекурсивный обход директорий с фильтрацией по именам и расширениям.
- Генерация ASCII-дерева структуры папок.
- Вывод содержимого текстовых файлов с настраиваемыми заголовками/подвалами.
- Гибкая система плагинов — легко добавить новый формат вывода или постобработку.
- Работа через JSON-конфиг: целевая папка, выходной файл, включённые плагины и их настройки.

## Установка

1. Склонируйте репозиторий:
   ```bash
   git clone https://github.com/ВАШ_НИК/dumper.git
   cd dumper
   ```

2. Убедитесь, что используется Python 3.8+ (файл `.python-version` может указывать конкретную версию).

3. Никаких внешних зависимостей не требуется — только стандартная библиотека Python.

## Использование

Запуск с конфигом по умолчанию:
```bash
python main.py
```

С указанием своего конфига:
```bash
python main.py path/to/config.json
```

С подробным выводом логов:
```bash
python main.py -v
```

После выполнения дамп будет сохранён в файл, указанный в конфигурации.

## Формат конфигурации

Конфигурационный JSON-файл должен содержать следующие поля:

| Поле               | Тип       | Описание |
|--------------------|-----------|----------|
| `target_directory` | `string`  | Путь к целевой директории, которую нужно обработать. |
| `output_file`      | `string`  | Путь для сохранения итогового дампа. |
| `plugins`          | `object`  | Словарь, где ключ — `host_key` плагина, значение — его настройки. |

### Пример `configs/full_dump.json`

```json
{
  "target_directory": ".",
  "output_file": "dumps/full_dump.txt",
  "plugins": {
    "directory_structure": {
      "enabled": true,
      "exclude_names": [".git", "__pycache__", "dumps"],
      "strategy": null
    },
    "file_contents": {
      "enabled": true,
      "exclude_names": [".git", "__pycache__"],
      "exclude_extensions": [".pyc", ".log"],
      "include_extensions": ["*"],
      "block_header_template": "===== Файл: {relative_path} =====",
      "block_footer_template": "===== Конец: {relative_path} ====="
    }
  }
}
```

### Параметры плагинов

#### `directory_structure`

- `exclude_names` — список имён файлов/папок, которые нужно исключить из дерева.
- `include_names` — если задан список (не `["*"]`), включает только указанные имена.
- `strategy` (задел на будущее) — стратегия комментирования узлов.

#### `file_contents`

- `exclude_names` / `include_names` — фильтрация по имени файла.
- `exclude_extensions` / `include_extensions` — фильтрация по расширению (например, `[".txt", ".md"]`).
- `block_header_template` / `block_footer_template` — шаблоны обрамления блока с файлом. Доступна подстановка `{relative_path}`.
- `strategy` (задел) — постобработка содержимого файла.

## Архитектура плагинов

Все плагины наследуются от абстрактного класса `DumperPlugin` (`project/blank_plugin.py`).  
Каждый плагин обязан определить:

- `host_key: str` — уникальный идентификатор, используемый в конфиге.
- `name: str` — человекочитаемое имя для логов.
- Метод `execute(target_directory: str, output: TextIO) -> None` — генерация своей секции дампа.

Плагины автоматически обнаруживаются в папке `project/plugins/`.  
Включение/отключение и передача параметров осуществляется через соответствующий блок в `plugins` конфига.

### Добавление нового плагина

1. Создайте файл `project/plugins/my_plugin.py`.
2. Реализуйте класс, наследующий `DumperPlugin`.
3. Поместите логику в `execute`.
4. Укажите настройки плагина в конфиге, используя тот же `host_key`.
